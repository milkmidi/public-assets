把上面三個黏起來的程式
全部免費建議先照 Part 1–3 把核心跑通（先不碰 LINE），確認沒問題再接 LINE。
1
PART 1建立試算表 + 打開 Apps Script
1-1到 sheets.google.com 建立一個新的空白試算表，命名例如「行政助手」。
1-2看網址列，複製中間那串 試算表 ID（等一下要用）： 
https://docs.google.com/spreadsheets/d/【這一整串就是 SHEET_ID】/edit
1-3上方選單點 擴充功能 → Apps Script，會跳出新分頁，這就是寫程式的地方。
1-4看到預設檔案 Code.gs，全選刪掉，把提供的 Code.gs 內容整段貼上，按 Ctrl / Cmd + S 存檔。
2
PART 2設定三把金鑰（指令碼屬性）

金鑰不寫死在程式裡，放在安全的地方讀取。

2-1Apps Script 左側點 齒輪圖示（專案設定）。
2-2捲到 「指令碼屬性」 → 新增指令碼屬性，加入三筆：
屬性名稱值
SHEET_IDPart 1-2 複製的那串
GEMINI_API_KEYPart 3 會拿到
LINE_CHANNEL_ACCESS_TOKENPart 4 會拿到
先把 SHEET_ID 填好，另外兩個等拿到再回來補。每次修改後按「儲存指令碼屬性」。
3
PART 3申請 Gemini API Key（並測試 AI）
3-1到 aistudio.google.com/apikey 用 Google 帳號登入。
3-2點 Create API key，複製產生的金鑰。
3-3回 Apps Script 專案設定，填進 GEMINI_API_KEY，儲存。
3-4先測一次。回程式碼畫面，上方函式下拉選 setupSheetHeader，按 執行。
第一次會跳「需要授權」→ 審查權限 → 選帳號 → 進階 → 前往「專案名稱」(不安全) → 允許。這是程式要動你的試算表，正常授權，只有第一次要做。
執行完回試算表，第一列應該多了「建立時間、對象、日期…」標題。
3-5再選 testWithoutLine 執行一次。成功的話試算表會多一列「王小明／看房」的資料。
✅ 到這裡，就算完全不接 LINE，核心功能已經會動了。
4
PART 4申請 LINE 官方帳號 + Messaging API
4-1到 developers.line.biz 登入 → 建立一個 Provider（隨便取名）。
4-2在該 Provider 下建立一個 Messaging API channel（填基本資料即可）。
4-3進 channel → Messaging API 分頁 → 最下方 Channel access token 按 Issue 產生 token，複製。
4-4回 Apps Script 專案設定，填進 LINE_CHANNEL_ACCESS_TOKEN，儲存。
5
PART 5部署成網頁應用程式（產生 Webhook 網址）

這步是「零成本後端」的核心 —— 把 GAS 變成 LINE 打得到的公開網址。

5-1右上角點 部署 → 新增部署作業。
5-2點左邊 齒輪 → 選「網頁應用程式」。
5-3設定（這兩個選錯 LINE 就打不進來）：
欄位要選
執行身分 Execute as我（你自己）
誰可以存取 Who has access所有人 Anyone
5-4按 部署，複製結尾為 /exec 的網址。這就是你的 Webhook URL。
6
PART 6把 Webhook 網址接回 LINE
6-1回 LINE Developers → Messaging API 分頁 → Webhook URL 貼上網址 → 按 Update。
6-2按 Verify 測試連線。⚠ 這裡幾乎一定會跳 302 紅字，是正常的，直接無視（原因見下方情境卡）。
6-3把 Use webhook 開關打開。
6-4關掉系統預設自動回覆（不然會跟程式打架）：到 Auto-reply messages（LINE Official Account Manager），把自動回應訊息關閉、Webhook 開啟。
6-5真正的驗證方式：別看 Verify 紅字，直接傳訊息實測。加官方帳號好友，傳一句：
「陳先生明天下午兩點要來看貨，地點在新北市板橋區文化路一段 50 號」
🎉 收到「✅ 已記錄」回覆、試算表多一列、日曆多一筆提醒 → 整條路就通了。
一定會遇到 · 先看這裡

關於那個 302 錯誤

在 LINE 按 Verify 時跳出的紅字：

The webhook returned an HTTP status code other than 200.(302 Found)

這不是你的錯，也不用修——它是 Google Apps Script 的正常行為。GAS 的網址對每個外部請求都會先回一個 302，把對方「轉址」到另一個真正執行程式的網址，內容要跟著轉址走才拿得到。

會不會出問題，取決於呼叫方願不願意跟著轉址走：

呼叫方會跟隨轉址嗎結果
瀏覽器 / 手機 LINE App✅ 會正常運作
LINE 的 Verify 按鈕❌ 不會只看到 302 → 報錯

所以會出現一個弔詭但正常的情況：Verify 顯示失敗，但實際傳訊息完全正常。正確做法是無視 Verify，用「實際傳一則訊息」來驗證。訊息有進試算表 = 成功。

最容易漏 · 改完必做

改完程式碼，一定要重新部署

你每次修改 Code.gs 存檔後，LINE 那邊不會自動更新。一定要手動重新部署新版本：

  1. 右上角 部署 → 管理部署作業
  2. 點部署右邊的鉛筆（編輯）
  3. 版本下拉選 「新版本」（這步最關鍵，選錯就是沿用舊程式）
  4. 按 部署

網址不會變，不用重貼給 LINE。如果你改了程式卻發現「行為跟改之前一樣」，九成就是漏了這步。
