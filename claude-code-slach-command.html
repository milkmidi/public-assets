一、會話管理

/clear

清空當前對話，開始一個全新的會話。

當你做完一個任務，要切到下一個任務時，用 /clear 可以把之前的上下文全部清掉，避免舊資訊干擾新任務。

/rename

在 /clear 前，可以先為這次的對話 rename 成一個自己好識別的名字，單純給人類識別用，沒其他特殊功能。

如果不用 rename，你就需要記得對話的 section ID，But，誰會記得呀，還是乖乖用 /rename。

/compact

壓縮當前對話，釋放上下文空間。

所有的 Model 都有 Context window（上下文窗口）的數量限制，聊著聊著就滿了。一旦上下文接近上限，通常 70% 左右，AI 的注意力會開始渙散，容易遺漏之前討論過的細節，回答品質明顯下降，就是變笨啦。

/compact 會把之前的對話濃縮成一份摘要，騰出空間繼續工作，同時保留關鍵資訊不丟失。壓縮後的對話輪次更少了，後續每次請求傳送的 token 也會減少，相當於間接幫你省錢。

雖然 Claude Code 在上下文達到大約 95% 時會自動觸發壓縮，但建議不要等到那時候才處理。自動壓縮的時機不可控，可能正好在你實現關鍵邏輯的時候觸發，導致重要細節被壓縮掉。
最佳做法：在每完成一個階段性任務後（比如做好了一個動畫腳本、或是寫完一份規格書），就主動執行一次 /compact。你還可以在後面加指令，告訴它重點保留什麼，例如：
/compact 重點保留加薪規則的設計決策
/resume

想要接續過去的對話，可以使用 /resume 恢復之前的會話。

假如你昨天做到一半的任務今天想接著做，或者剛才 /clear 掉的對話需要回去看看，都可以用 /resume 來恢復。直接輸入後，會彈出一個會話選擇器，列出你最近的所有會話，選一個就能恢復。

/recap

生成當前會話的一句話摘要。

如果你離開了一會兒回來，忘了剛才做到哪了，/recap 可以快速幫你回憶。其實 Claude Code 本身在你長時間離開後回來也會自動顯示一個 recap，這個命令是讓你隨時主動觸發。

/btw

btw 就是 by the way 的縮寫，作用是快速插入一個問題，不會污染當前對話上下文。

有時候你正在做一個任務，突然想問一個不太相關的小問題，比如：「你的文件資訊是從哪得到的？」如果直接問，這段對話會被加到上下文裡，不僅佔用空間，還可能干擾後續任務。用 /btw 就不會有這個問題，它相當於開了一個臨時小窗，問完就關。

/copy

把 Claude 最近一條回覆內容複製到剪貼簿。直接輸入 /copy 就是複製最新的回覆。

/export

把當前整個對話匯出為純文字檔。如果你想保存一段對話記錄，或者分享給同事看，可以用這個命令。默認會讓你選擇複製到剪貼簿還是保存到檔案。

/export 會議對話記錄.txt
/exit

退出 Claude Code 會話。或連按兩次 Ctrl+C 也能退出。

二、資訊與診斷

/usage

查看當前會話的 token 用量和費用。

用 Claude Code 最怕的就是不知不覺燒了很多錢。/usage 會告訴你這次會話花了多少 token、換算成多少美元、離你的計畫用量上限還有多遠。建議在長時間工作後定期看一眼。

或是你財富自由，就可以不用看。啾咪 ^()^

/context

可視化當前的 Context Window 的使用情況，非常重要，在這你可以看到是不是要塞滿了。

執行後會顯示一個彩色網格，直觀地告訴你 Context window 被什麼東西佔滿了：是對話記錄太長、還是載入的檔案太多、還是系統提示詞太大。如果快滿了還會給出最佳化建議。

/status

打開設定介面的狀態標籤頁，顯示當前的版本號、使用的模型、帳戶資訊和連接狀態。不是那麼的重要，看看就好。

/insights

生成一份你使用 Claude Code 的分析報告，包括你經常在哪些項目目錄工作、互動模式是怎樣的、哪些地方產生了問題。

使用建議：如果你想回顧自己的 AI 程式設計習慣、找找最佳化空間，可以定期跑一次看看。生成出來的報告默認是英文的，你可以把報告檔案扔給 AI，讓它再幫你分析總結。

三、模型和模式控制

/plan

在開發大型專案、或者做大改動之前，不建議直接讓 AI 直接開始寫任何東西。

使用 /plan 可以進入規劃模式，會讓 AI 先制定一個執行計畫給你看，確認方案沒問題後，再動手實現。

也可以直接按 Shift + Tab 切換到 plan 模式。
/goal 新功能 🔥

這是目前 Claude Code 最強大的命令之一。一般情況下，Claude Code 每完成一輪操作，就會停下來等你確認或者下一步指示。

但有些任務你其實不需要盯著它一步步做，只需要告訴它「最終達到什麼狀態就算完成」，讓它自己埋頭苦幹。特別適合睡覺前丟一個任務給它，第二天早上起來直接驗收成果。

/goal 命令就是幹這個的。你設定一個完成條件，Claude Code 會自動持續工作，不需要你每一輪都按同意確認。設定了 goal 之後，每輪結束會有一個輕量評估模型檢查條件是否滿足，沒滿足就自動開始下一輪，滿足了才停下來。

/goal 掃 source 資料夾下所有的 xlsx 檔，並確保所有的加薪不超過 5%，請用科學方式驗證，例如執行 python 來驗證，不要亂猜
goal 難的不是執行，而是你怎麼讓 AI 驗證是對的，然後才能進行下一步。

四、Config

/mcp /skills /plugin

這三個命令分別用來管理 MCP Server、Skills 與 Plugins。

  • MCP：讓 AI 連接外部工具和服務的協議，比如連接 Google 的服務、操作瀏覽器。
  • Skills：可復用的自訂命令，你可以把常用的工作流封裝成一個 skill，下次更快速規範地完成任務。
  • Plugin：技能的打包集合，一個外掛裡可以包含多個 skill、自訂主題、hook 等，方便分享和安裝。

五、程式碼審查

/simplify

雖然這個命令的名字叫 simplify，但它干的事不只是簡化程式碼。它的核心作用是審查你最近修改的檔案，從三個維度找問題並直接修復：

  • 程式碼復用：有沒有重複邏輯可以抽取
  • 程式碼質量：有沒有 hack 寫法和冗餘狀態
  • 執行效率：有沒有不必要的計算、可以並行的地方

之所以叫 simplify，大概是因為這三個方向做下來，程式碼確實會變得更簡潔。
